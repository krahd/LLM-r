# 0.6.9 VST3 UX/Runtime Audit (Prompts 16-22)

Date: 2026-05-21
Branch: fix/0.6.9-vst3-ux-runtime-blockers

## Confirmed defects from audit

1. Execute incorrectly followed the Dry run preference (`executeLastPlan(currentDryRunDefault())`), so Execute could silently behave as preview.
2. Prompt entry used a single-line field (`LlmrPromptField : NSTextField`) with limited composer ergonomics.
3. Main UI readiness strings were ambiguous (`AbletonOSC not checked`, `Bridge optional`, `Dry run on/off`).
4. Planner timeout could block indefinitely waiting for provider response.
5. Built-in fallback only covered a short 2-bar drum loop and did not support longer duration requests or piano requests.
6. Startup had first-use checks that could trigger intrusive UI on attach (installation prompts), creating perceived startup friction.

## Implemented repairs

### Execution semantics

- Execute now routes through `executeFromMainButton()` and no longer follows a dry-run default mode.
- Added explicit safety preference semantics: `Require dry-run before execute`.
- Added per-plan dry-run tracking (`hasDryRunCurrentPlan_`).
- Execute prompt now offers: `Run Dry Run`, `Execute Anyway`, `Cancel` when dry-run is required and missing.
- Execution report/status labels are explicit: `DRY RUN`, `SENT`, `BLOCKED`, `ERROR`.

### Main UI and wording

- Prompt composer replaced with multiline `NSTextView` (`LlmrPromptTextView`) in a scroll view.
- Added System Prompts entry point in header.
- Updated readiness label wording:
  - `AbletonOSC: not tested` / `configure host/port`
  - `Device Bridge: available/not reachable/only needed for devices`
  - `Safety: dry-run required/optional`
- Removed startup auto-check dispatch in editor attach path to reduce startup blocking behaviour.

### System Prompts window

- Added fixed window with preset selector + multiline editor.
- Added actions: Save, Save As, Load, Reset Default, Cancel.
- Added persistence keys:
  - `llmr.vst3.system_prompt_preset`
  - `llmr.vst3.system_prompt_custom`
- Added save-time warning if custom prompt appears schema-unsafe.
- `systemPrompt()` now composes selected/custom base + `toolCatalogPrompt()` + optional extra guidance.

### Musical duration and fallback reliability

- Added helper functions:
  - `parseRequestedDurationBeats(prompt, tempo)`
  - `isDrumCompositionRequest(prompt)`
  - `isPianoCompositionRequest(prompt)`
  - `buildJazzDrumPlan(durationBeats, tempo, humanise, variation)`
  - `buildPianoBalladPlan(durationBeats, tempo, key, style)`
- Drum fallback now scales clip length to requested duration instead of fixed 2 bars.
- Added piano fallback path for non-JSON/failed responses.
- Fallback explanations explicitly document Session fallback when Arrangement insertion is unsupported.

### Timeout/repair behaviour

- Added bounded provider timeout in `callLLM` (90s) with explicit timeout error.
- Existing repair pass remains in place; fallback now covers drum and piano request classes.

- Added static regression tests:
  - `tests/test_vst3_fallback_static.py`
  - `tests/test_vst3_system_prompts_static.py`

  - `tests/test_vst3_settings_side_effects.py`

## Remaining risk / follow-up

1. Enter-to-submit behaviour in multiline composer remains conservative to avoid host key-interception regressions; manual UX pass in Ableton is required.
2. Arrangement-view targeting remains constrained by available action layer capabilities; Session fallback messaging is in place, but full arrangement insertion tooling is still a roadmap item.

## Prompt-sequenced implementation plan (completed items)

- UI: multiline composer, clearer readiness labels, reduced startup blocking checks.
- Settings: safety semantics rename and persistence migration (`require_dry_run_before_execute`).
- Execution: strict Execute vs Dry run split, pre-exec dry-run gating, plan-level tracking.
- Prompt-system: editable/persisted System Prompts window and composed planner prompt pipeline.
- Reliability: duration parsing, richer deterministic fallback generators, bounded timeout.
